# 首次使用计分与独立交接

[English](FIRST_PILOT_EN.md) · [试点计时](PILOT_CN.md) · [项目用途模板](SITE_DELIVERY_CN.md)

**邀请工程师前**，负责人用 `python scripts/first_pilot.py --out <新目录> --case pagosa --release <签名发行目录/RELEASE.json> --source <起始资料>` 建立一份试点记录。另对 `midway` 与 `dexter` 各执行一次，每份起始文件各传一次 --source。Pagosa 可把地址或坐标与两座桥名写在同一份资料中。原件本地保管。工具登记原件指纹、发行清单和预定任务，生成空白计分表与接收记录。此操作不计时、不签审。管理员另行核验发行签名。

| 路线 | 起始资料 | 任务与停止条件 |
| --- | --- | --- |
| 仅坐标 · Pagosa | 科罗拉多州 Pagosa Springs，250 San Juan St；US 160／First Street 至 Hot Springs Boulevard，两桥均排除。 | 找到 Q100 与地形依据或记录缺口，确认边界，初筛河段并定位边界影响。控制资料不足时停下或明确条件性用途。 |
| 部分资料 · Midway | Jeff 最初提供的坐标和原件。已建模型及此前采用的估值不进入起始资料。 | 核对各组净尺寸，索取缺失涵底；收到测量时核对，假设性演练须标注。建立独立修订版重算、对照、选版。 |
| 完整测量 · Dexter | 认可的测量包、事件流量、出口控制、独立内点水位及现有精度说明。 | 分清边界和核验点，生成双包并定位实测偏差。原件未给测量精度时保留该限制。 |

三例合计至少包含一次导出失败恢复和一次旧版本被替代。打开最小包模型及完整包报告，追溯到选定运行，并指出一个尚存限制。接收人只拿客户交接包，独立记录版本、用途、限制及下一步允许动作。

**计分。** 每条路线的分母包括所有已启动的场地、失败和中止。仅当首次尝试中两包清单均通过校验时计为首次出包成功。因资料不足而正确停下的任务单列。独立完成要求开发者介入为零、假设均有标识、用途判断正确；要求交付的任务须完成双包核验，要求识别缺口的任务可在正确停下后通过。使用内置说明和操作指南允许，求助须记录。范围不适用、版本归属不明、必要资料不足或工作盘空间不足时停下。

从项目试点记录中取得工程师主动工时、等资料、卡点和开发者介入。机器任务及求解时间分别列出。每个卡点写明路线、步骤、用户预期与实际现象。未知工时留空。负责人可在开始前与公司手工基线约定时间目标。当前记录不承诺人时节省或响应时限。

**分工与签审。** 操作人填写 scorecard.csv。另一位工程师填写 recipient.md，核对用途、模型和报告归属、图件限制、签发状态及退回意见。试点负责人填写通过、条件使用或停止，并登记问题与责任人。自动演练及空白表本身均不产生这些签审结论。

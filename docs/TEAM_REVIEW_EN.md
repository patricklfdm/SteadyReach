# Formal team review and client issue

[简体中文](TEAM_REVIEW_CN.md)

Open a calculated edition and go to **Results → Delivery → Formal team review and client issue**. Routine calculations can be completed without entering operator names. The formal record is linked to the project edition, solver run, native HDF and calculation summary.

1. The modeler selects **Submit this edition** with the intended recipient or question. The current package and summary must match.
2. A different operator chooses a river station or one or more hydraulic inputs and enters a review note. **Return for revision** preserves the question. For offline review, download the HTML form, send it to the reviewer and import their returned JSON. Preview the author, station and note before recording. A reply for a different edition or an earlier review round requires a new form.
3. Make a separate revision, calculate it and inspect **Earlier decisions affected by this edition**. Each comment lists the input fingerprints that changed. The other referenced inputs carry forward. Submitting the revised edition marks the returned ancestor as superseded.
4. A reviewer records the conclusion for the stated use. A lead previews both inventories and issues the client folders. Send only the **Client** folder. It contains the two scoped packages, both full report PDFs, native model and applicable map products. The **Internal** inventory stays on the workstation with the review history and original unfiltered project packages. Read the technical report for open hydraulic conditions.
5. Withdraw the issue if needed. The local history records the withdrawal. Notify recipients separately about previously transferred copies.

Operator labels identify locally declared responsibility. Independent professional sign-off and controlled identity management require the firm's own process. Every issue is read-only in normal operation. Create a separate revision for changes.

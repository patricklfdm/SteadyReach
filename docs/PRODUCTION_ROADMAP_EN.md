# Production priorities for 1D steady-flow work

[简体中文](PRODUCTION_ROADMAP_CN.md)

The first production use is a local Windows workstation where an engineer prepares a single-reach screening study, compares steady alternatives and hands a traceable HEC-RAS, GIS and report package to a colleague. Set release criteria against those tasks. Leave other hydraulic representations and cross-machine acceptance for a separate decision.

| Priority | Development | Evidence required to close |
|---|---|---|
| 1. Define the engineering decision | Agree with the reviewing engineer on the intended decision, event, reach limits, acceptable error and evidence required to use a result. Carry that decision into both reports. Flag projects requiring bridge hydraulics, split flow, flood timing or another representation at intake. | Freeze the criteria before the verification run. Demonstrate one applicable case and one case redirected at intake. A failed observation check stays visible on the cover. |
| 2. Validate field performance | Extend the existing Siletz and Big River comparisons with independent events and sites, observed stage, survey uncertainty, matched flow, vertical reference and representative low and flood flows. Reserve holdout observations before calibration. | Record bias, maximum residual, location and event, measurement uncertainty and the number of usable independent points. Exclude prescribed boundary stages from accuracy scores. Document an engineer's decision on each site's intended use. |
| 3. Make data gaps actionable | Extend source checks to data age, coverage, event alignment, rating validity, gage-zero changes and missing bathymetry. Cache raw pages and preserve the previous edition. Show the one missing input that most affects the decision, who can supply it and where it will be used. | Replay a valid project offline, distinguish service failure from an empty result, and show that a nearby gage with an unverified stage transfer remains conditional. An engineer supplies or accepts the transfer or requests a survey. |
| 4. Rank hydraulic risks | Link native messages to section geometry, flow partitions, boundary influence and observed residuals. Rank changes by impact on the intended decision. Preserve accepted geometry, compare every alternative against it and retain discarded alternatives. | Repeat the Merced overbank and Pagosa boundary cases. Report affected stations, maximum stage change, wet endpoints and new warnings. Flag an alternative that reduces warnings but worsens observed or spatial agreement. |
| 5. Protect and recover deliverables | Extend existing job receipts, checksums, backups and per-PDF recovery with project upgrade/rollback tests, a portable diagnostic bundle, package privacy controls, and release manifests including dependency inventory, supported tools and artifact verification. | On one workstation, interrupt a job, simulate an upstream outage and import an older project. Recover valid outputs with their run identities. Demonstrate a sanitized client handoff and a verified rollback. |
| 6. Measure engineer use | Observe a first-time engineer using coordinates, partial sources and a complete survey. Track first-attempt paired deliveries, active engineering time, machine time, external waiting, developer interventions and why a project stopped. | Agree pilot targets in advance. Publish counts and denominators by input route. Have the engineer complete one full project and another engineer reopen its package. Independently record their feedback. |

Start priorities 1 and 2 with Jeff's review of the frozen Siletz case. Its retained January 2018 interior residual was +0.524 m against a 0.15 m investigation threshold even though an identical-input rerun reproduced all 18 sections. Soquel exercises off-site boundary transfer. Big River exercises smaller observed residuals with missing measurement uncertainty. Use different sites for each claim.

The USACE steady-flow tutorial uses observed stages and tests downstream boundary and roughness sensitivity. FEMA's general hydraulics guidance adds agreement among the model, profiles, maps, discharges and high-water marks. They inform the technical review. NIST SSDF provides a reference for release integrity and recovery. Any jurisdictional deliverable needs its own applicable requirements. ## Iterations and acceptance on one workstation

The target is a single-reach 1D steady workflow starting with a location, site records or surveyed inputs. Native solves, DEM sections, input confirmation, use grades and paired deliveries already exist. The remaining gaps concern choosing the next action, deciding between revisions, explaining the deliverable to a recipient and recovering the correct task.

| Stage | Software change | Real acceptance sites and checks |
|---|---|---|
| 1. Intake and resumption | Prioritize geometry blockers, conflicting sources, available candidates and required external inputs for the current draft. Open the relevant tool and export a returnable worksheet scoped to current gaps. | Midway and Big River. Exercise incomplete and measured inputs, reopen after editing, import returned values and verify the calculation consent gate. |
| 2. Hydraulic review and alternative comparison | Compare corresponding profiles and common sections, water levels, wet ends, native warnings and coverage. Identify alternatives where fewer warnings accompany regressions or insufficient evidence. | Midway and Merced. Verify run identity, actual differences and stations; distinguish unknown flows and incomparable cases. |
| 3. Engineering handoff | Export a recipient-readable note bound to the run with permissible use, open issues, report paths and verification identity. Keep it with the two copyable packages and verify edition changes. | Midway and Soquel. Check both languages, real files and run identity; simulate a missing or mismatched file and identify the affected item. |
| 4. Recovery and release | Route preparation, solver and export failures to the appropriate recovery step; replay frozen inputs and bind newly computed outputs to the new packages. | Midway and Siletz. Exercise interruption or missing-file recovery, duplicate submission protection and same-machine native replay. Compare native water levels and flows. |

Each stage uses Midway and a different river drawn at random without replacement from five prior sites. The stage assignments were drawn before implementation. Record real inputs, actions and verifiable outputs for every stage. Report software acceptance separately from hydraulic approval, independent engineer timing and cross-machine release qualification.

### Results on the acceptance workstation

All four stages were exercised in isolated Windows copies. Returned worksheets preserved the source classification and identified remaining inputs. Both Midway and Merced had revisions with fewer warnings and a water-level change exceeding the 0.10 ft screening threshold. The recipient pages opened the matching reports, exhibits and project files. Removing an exhibit produced an error naming its package and relative path. Independent same-input runs reproduced the baseline water level and flow at all seven Midway sections and all 18 Siletz sections, with zero maximum absolute difference at output precision.

This evidence supports an engineer-supervised pilot on the tested workstation. Independent engineering review, a timed project by a new user and cross-machine qualification remain open.

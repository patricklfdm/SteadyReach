## Proposed enterprise roadmap, P5–P10

The P4 baseline runs a native 1D steady-flow calculation on Windows, supports independently confirmed revisions and field returns, assesses the project purpose, and produces bilingual reports and two verifiable delivery packages. Each phase below retains earlier native regressions, adds a failure or counterexample, and records the input edition, run identity, verdict and reproduction steps. The proposed software acceptance targets are separate from the engineering tolerances agreed for each site.

| Phase | What changes for the engineer | Development milestones | Same-workstation acceptance |

## Iterations and acceptance on one workstation

The target is a single-reach 1D steady workflow starting with a location, site records or surveyed inputs. Native solves, DEM sections, input confirmation, use grades and paired deliveries already exist. The remaining gaps concern choosing the next action, deciding between revisions, explaining the deliverable to a recipient and recovering the correct task.

| Stage | Software change | Real acceptance sites and checks |
|---|---|---|
| 1. Intake and resumption | Prioritize geometry blockers, conflicting sources, available candidates and required external inputs for the current draft. Open the relevant tool and export a returnable worksheet scoped to current gaps. | Midway and Big River. Exercise incomplete and measured inputs, reopen after editing, import returned values and verify the calculation consent gate. |
| 2. Hydraulic review and alternative comparison | Compare corresponding profiles and common sections, water levels, wet ends, native warnings and coverage. Identify alternatives where fewer warnings accompany regressions or insufficient evidence. | Midway and Merced. Verify run identity, actual differences and stations; distinguish unknown flows and incomparable cases. |
| 3. Engineering handoff | Export a recipient-readable note bound to the run with permissible use, open issues, report paths and verification identity. Keep it with the two copyable packages and verify edition changes. | Midway and Soquel. Check both languages, real files and run identity; simulate a missing or mismatched file and identify the affected item. |
| 4. Recovery and release | Route preparation, solver and export failures to the appropriate recovery step; replay frozen inputs and bind newly computed outputs to the new packages. | Midway and Siletz. Exercise interruption or missing-file recovery, duplicate submission protection and same-machine native replay. Compare native water levels and flows. |

Each stage uses Midway and a different river drawn at random without replacement from five prior sites. The stage assignments were drawn before implementation. Record real inputs, actions and verifiable outputs for every stage. Report software acceptance separately from hydraulic approval, independent engineer timing and cross-machine release qualification.

### Results on the acceptance workstation

All four stages were exercised in isolated Windows copies. Returned worksheets preserved the source classification and identified remaining inputs. Both Midway and Merced had revisions with fewer warnings and a water-level change exceeding the 0.10 ft screening threshold. The recipient pages opened the matching reports, exhibits and project files. Removing an exhibit produced an error naming its package and relative path. Independent same-input runs reproduced the baseline water level and flow at all seven Midway sections and all 18 Siletz sections, with zero maximum absolute difference at output precision.

This evidence supports an engineer-supervised pilot on the tested workstation. Independent engineering review, a timed project by a new user and cross-machine qualification remain open.

## P2 on one workstation

| Order | Engineering question | Software acceptance criterion |
|---|---|---|
| 1 | Did widening the section change the wet end on the affected side? | Compare water surface minus native endpoint elevation by profile, station and side. Track newly wet, still wet, now dry and dry in both editions. Changed reach, unmatched centers, missing records or ambiguous direction leave an unmatched item. |
| 2 | Can sender and recipient explain the same revision? | Compare the native results on the edition page. Carry the same endpoint counts and model-specific metrics into both full reports and the offline start pages. Show unknown values and unavailable differences explicitly. |
| 3 | Did the complete selected edition arrive? | Open a start page offline, choose the copied folder, verify the guides, package manifests and members. Identify a missing, edited or mixed-edition report by its relative path. |
| 4 | Does the software pass for a measured river as well as a culvert? | Run the P2 release command in an isolated checkout. Repeat Midway from the originals and Siletz from the frozen survey. Verify the river revision, compare every native stage and flow to the reference, and score the independent interior event separately. |

The P2 gate covers software on the acceptance workstation. Investigation thresholds remain specific to each project. Independent sign-off, first-use timing and cross-machine qualification require separate evidence. See the [local release guide](LOCAL_RELEASE_EN.md).

**Same-machine acceptance, November 24, 2026.** The P2 gate passed 477 Python checks and 43 page regressions with five fresh HEC-RAS calculations. In Midway, widening RS 2600 from 160 to 170 ft left its right endpoint wet (1.178 to 1.214 ft of water at the respective endpoints). The river replay reproduced stage and discharge at all 18 Siletz sections at native output precision. The fresh January 2018 holdout stage at interior RS 44056 was 0.524 m above observation, exceeding the 0.15 m investigation threshold. The downstream boundary was excluded from scoring. Both languages showed the same edition summary; the offline folder checker located a missing, edited or wrong-edition report in three separate trials.

## P3 from source records to recipient handoff

Start three projects from the home page. For Midway, save the draft and request missing information from the site pin and original field documents. Review the openings and exterior channel against terrain and imagery, then use the reviewed points to resolve crossing sections before confirming the calculation. Recalculate a separate edition when the road evidence arrives. For Siletz, import the survey folder and compare the withheld interior stage with the native result for the same event. Check both report languages and the offline landing page. At a third surveyed site, apply the site's own purpose and conditions and check the returned profiles and sections against the supplied records. Independently check the archived native result for the East Fork event.

Before selecting an edition, inspect common-section water levels, wet ends on the same bank and changes in overbank discharge. Either the earlier run or the revision can be handed over. The recipient can trace the selected run, rationale, limitations, open evidence requests and original records from the start page. See the [local release guide](LOCAL_RELEASE_EN.md) for inputs and commands.

At Midway, using the open channel interpreted from the imagery and DEM cleared all 10 intersecting section pairs at the original search extent. All 22 sections had terrain elevations. Six sections had a wet end in the revised Q100 case, and surveyed culvert inverts remain outstanding. At Siletz RS 44056, the observed stage was 46.3311 m and the modeled stage was 46.8551 m. The residual exceeded the site’s 0.15 m investigation threshold. The boundary at RS 34913 was excluded from scoring. The separate Big River / Rockford survey completed handoff with nine sections at 3,919.93 cfs. The offline browser identified missing, edited and wrong-edition reports. Independent first use, engineering sign-off and cross-machine qualification remain open.

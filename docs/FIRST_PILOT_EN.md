# First-use pilot record and independent handoff

[简体中文](FIRST_PILOT_CN.md) · [Pilot clock](PILOT_EN.md) · [Site delivery templates](SITE_DELIVERY_EN.md)

**Before inviting anyone**, the pilot lead creates a fresh folder with `python scripts/first_pilot.py --out <new-folder> --case pagosa --release <signed-release/RELEASE.json> --source <starting-record>`. Repeat for `midway` and `dexter`. Specify --source once for each supplied file. For Pagosa give the site location and two bridge names in one starting record. Keep originals privately. The generator records their hashes, the release manifest identity and the predetermined tasks. A folder starts with an empty scorecard and recipient record. Creating it starts no clock and performs no sign-off. Administrators verify the release signature separately.

| Input route | Starting material | Tasks and stopping conditions |
| --- | --- | --- |
| Coordinates · Pagosa | 250 San Juan St, Pagosa Springs, CO; US 160 / First Street to Hot Springs Boulevard, both structures excluded. | Find or document Q100 and terrain, confirm limits, screen the reach and locate boundary influence. Stop for missing control or document the allowed conditional use. |
| Partial · Midway | Jeff’s original coordinate and materials, without previous model or accepted estimates. | Trace group dimensions, request missing inverts, review a returned measurement or label an assumed rehearsal. Recalculate a separate revision, compare and select an edition. |
| Surveyed · Dexter | Complete approved survey package, event flow, documented outlet and independent interior observation with its available accuracy. | Keep boundary and holdout roles separate. Generate both packages and locate the measured discrepancy. An undocumented accuracy stays open. |

Across the three cases exercise one export retry and one superseded edition. Open the Minimal model and Complete report, trace both to the selected run, and explain one remaining limitation. Give the recipient only the client handoff, without developer coaching. They independently record the edition, purpose, open limitation and permissible next action.

**Scoring.** Record every started site, including a stop or failure, in the denominator for that route. Count first-attempt paired delivery only when both manifests verify on the first attempt. Record a correct evidence stop separately. Success for independent operation requires zero developer interventions, no unmarked assumptions, correct use limits and a verified handoff for a delivery task. A correct evidence stop succeeds on its own assigned task. Record help even if work resumes. Optional guides and on-page feedback are allowed. Pause on unsafe scope, unresolved identity, missing required data or insufficient space.

Use the project pilot clock for engineer time, external wait, blockers and developer help. Record machine task and solver time separately, and record the route, step, expected behavior and actual outcome for each obstacle. Leave unknown times blank. Before starting, the pilot lead may register an effort target against the firm's manual baseline. The evidence available today sets no labor saving or response-time promise.

**Roles and decision.** The operator completes scorecard.csv. A different engineer completes recipient.md and checks purpose, package identity, drawing limitations, approval status and any return for revision. The pilot lead records acceptance, conditional use or a stop with issue and owner. A local rehearsal or generated form does not supply these decisions.
